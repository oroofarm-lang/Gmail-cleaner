# Core safety and adversarial review

Scope: `packages/core/index.ts` and `tests/core`. This is a bounded domain library and fake execution reference, not a production Gmail worker or a learned classification model.

Gmail safety: PASS for tested reference scope; FAIL for production Gmail readiness. Category signals, exact protected sender matching, reply history, starred/important/sent/draft/custom labels, attachments and sensitive subject patterns gate cleanup. KEEP and REVIEW override destructive rules. Approval belongs to a server-owned plan, expires in 15 minutes, and is rechecked during execution. Previewed metadata is compared with current metadata, and current protection preferences are reloaded. Tenant-scoped calls, retries, partial failures, disabled operations, concurrent execution, duplicate execution, timeout after mutation and Undo are tested. The reference service refuses a live adapter because its plans, idempotency state and tenant locks are in memory.

Remaining production blockers: persist plans and per-message outcomes transactionally; distributed tenant locking; resumable background queue; OAuth-authenticated tenant identity at HTTP boundaries; quota handling; real Gmail integration tests. Gmail does not offer conditional mutation by metadata version, so policy changes between the last read and mutation need cancellation and bounded worker batches; this library cannot promise atomic external-mailbox decisions. A timeout reconciles the expected Trash state but cannot establish which independent actor moved a message. Restore removes Trash and restores previous Inbox membership, without overwriting subsequent user labels. Recovery cannot restore mail permanently removed by Gmail.

AI red team: PASS for deterministic boundary; external AI provider behavior NOT TESTED. Email subjects are only inputs to metadata classification and never interpreted as tool calls, URLs to fetch, system instructions or protection changes. Eight adversarial subjects are tested. The parser accepts a small explicit grammar, rejects chained/vague commands and marks new rules unapproved. There is no LLM confidence score: `confidence` is null and `source` is deterministic. Metadata heuristics are fallible and may miss important mail; candidate recommendations still require explicit preview approval.

Performance: synthetic 10k/50k/100k metadata cases verified complete aggregate counts. Measured generation 4/19/19 ms, aggregation 19/60/113 ms, process heap 14/46/77 MiB in the local Node 24 run. These are reference measurements; they do not measure Gmail throughput, database queries, browser rendering or live provider quotas.

Executed: 12 Node test cases passed, scoped strict TypeScript check passed. Run `node --experimental-strip-types --test tests/core/safety.test.ts` and `node --experimental-strip-types tests/core/benchmark.ts` from the repository root. The parent release review must assess live integrations independently.
