# Chrome dashboard companion

Build with `npm run build:extension`; load `dist/extension` unpacked in Chrome116+. Default builds are launchers with no external-message allowlist and no network access. Arbitrary dashboard URLs are links only and never receive secrets or approved summaries.

For the read-only relay, package an exact trusted HTTPS `INBOX_EXTENSION_ORIGIN`; the generated manifest allows only that origin and no extension IDs. The backend requires `INBOX_EXTENSION_RELAY=enabled`, the same exact origin, and the installed32-letter `INBOX_EXTENSION_ID`. Configure only through an authorized host flow. No live activation/install test was done. Both default build and backend remain disabled until configured.

Open the configured dashboard from the panel, sign in and choose Settings → Connect or refresh companion. The Chrome worker returns a random device ID/challenge; the authenticated same-origin backend stores only its SHA256 hash and a two-minute pending approval. Explicit approval grants read-only aggregate relay for30 days, bound to owner and current Gmail connection epoch. Approval is single-use. The extension cannot authenticate directly to the API or fetch mail. All cleanup/Undo stay in the dashboard.

Shared fields: synthetic/Gmail source, connection boolean, total/protected counts and action count. No subjects, sender/account addresses, mail content, OAuth/AI credentials or raw activity. Projection display expires after two minutes; refresh needs the open authenticated dashboard. Revocation prevents later server summaries; an already delivered projection remains displayable until its two-minute expiry. Local storage retains approved device ID/challenge and last aggregate projection until Forget, replacement or uninstall; hiding expired counts is not deletion. No Chrome sync storage is used. Storage is restricted to trusted extension contexts. Forget removes local approval/summary; separately revoke the device in the dashboard for server removal. Account deletion/data deletion erase server devices. Reconnect/disconnect invalidate approval through the connection epoch. Start new companion approval explicitly resets the local challenge and requires new user approval.

Only pinned-origin top-level dashboard messages are accepted; extension senders and other paths are rejected. Pending responses are tab-bound; packets require matching device/challenge, strict bounded fields and fresh monotonic timestamps. Reset/Forget/summary storage operations are serialized. No host permissions, content scripts, external fetch, remotely loaded code or Gmail DOM access. Browser contract tests and independent synthetic tests supplement server isolation/expiry/replay tests; live unpacked Chrome messaging, gateway behavior and Web Store acceptance remain UNVERIFIED release gates.

Primary contracts: [Chrome messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging), [external messaging allowlists](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable), [trusted-context storage](https://developer.chrome.com/docs/extensions/reference/api/storage).
